# Measured multi-asset operation and prospective validation

Baseline: `16ed91cdf0821bc5239548151bda14532e169285` (merged v0.8.0).
The user authorizes implementation and delivery through GitHub merge. Target:
100 concurrently monitored assets, extensible to 1,000 explicit asset identities.
Capacity depends on native markets, venues, cadence and retained vintages as well
as asset count. BTC/ETH remain defaults; syntax alone does not establish access.

## Acceptance

1. Provide a finite, restartable real-source operating acceptance path and read-only
   reports for completeness, freshness, failures, receipt lag and actual elapsed
   observation. Synthetic or injected checks cannot qualify real-source operation;
   blocked network access and unelapsed observation periods stay explicit.
2. Expose bounded per-source/task HTTP work and process-level resource evidence,
   separating logical operations, measured attempts, decoded bytes, unknown wire
   bytes and actual bills. Declared prices may estimate cost but cannot invent an
   observed charge. Plan collection demand and fair progress across large universes.
3. Freeze prospective evaluation criteria before observations, persist the protocol
   identity with original issuance, and evaluate only matching native/event/clock/
   model/cost cohorts. Preserve pending, missing, overlapping and excluded origins.
   Plan comparisons require funded execution evidence and a matching regular-purchase
   baseline. No probability calibration or financial edge is inferred from support.
4. Reduce repeated daily aggregation, feature construction and raw evidence copies.
   Offer explicit reference summaries while preserving full evidence mode and its
   limits. Reuse computations only when their exact snapshot/inputs are known.
5. Remove BTC/ETH restrictions from generic collection and mathematical analysis,
   retain source-specific capabilities, bound concurrency/memory and persist fair
   continuation. Never construct an unbounded queue or share an unsafe source client.
6. Compare actual SQLite, DuckDB/Parquet and PostgreSQL workloads before selecting
   storage roles. Preserve all vintages, native identities and deterministic ties.
   Bulk immutable analytical snapshots must not impersonate the live SQLite/journal
   snapshot. Record technology roles, measured trade-offs and migration triggers.

## Delivery

New local CLI operations are noninteractive, dry-run/read-only by default and
support structured requests. MCP exposes only bounded analysis/status operations.
No orders, paid APIs, permanent worker or public deployment is activated.
Independent Standards and Spec review use this baseline and plan. Final required
checks, actual CLI/MCP workflows and engine benchmarks record exact revisions.
Code, tests, examples and documentation are committed; generated databases, raw
reports, benchmark files and temporary container data remain outside Git.
